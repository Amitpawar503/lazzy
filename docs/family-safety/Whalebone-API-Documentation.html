Whalebone (Airtel Secure) — API Documentation

Swagger-style · Management on Retail API /3 (base /management) · Events on Public API v2 (base /whalebone/2, headers Wb-Access-Key + Wb-Secret-Key).
ID rule: deviceId = subscriptionId = MSISDN · Whalebone auto-creates device+user on subscription and auto-deletes after retention — Airtel never calls POST /management/devices, POST /management/users, or any DELETE.

Optimization — how Airtel consumes this surface

Whalebone's API is a partner contract (not changed by Airtel). The Channel BE / BFF collapses it for the app so ~18 Whalebone endpoints are driven by ~5 BFF-facing operations, enum-switched internally.

Whalebone groupEndpointsBFF-facing operationSwitch
Device config (filter / applications / scheduled-filter)6 GET/PUT1 BFF API — PUT|GET /parental/{msisdn}?resource=FILTER|APPLICATIONS|SCHEDULEvia resource enum
Allow / deny lists (whitelist + blacklist, add/remove/read)5 calls1 BFF API — …?resource=LISTS + listType + opvia listType/op enum
Subscription lifecycle (create/suspend/activate)3 POST1 BFF API — PUT /protection/{msisdn} {type,action}via action enum
Device create / user create / delete—Not called — Whalebone auto-creates & auto-deletesAirtel never calls

See Family-Safety-API-Binding-Leadership for the upstream↔downstream enum mapping.

Read/write rules (from HLD): GET-merge-PUT every filter / applications / scheduled-filter — send the full intended policy; omitted threat/content types become unblocked; keep all 7 threats true. Allow/deny list add & remove need no prior GET. Stats: always pass days (max 220), cache 24h per MSISDN, back off on 429. Suspend/activate carry no body.
To confirm with Whalebone (gaps): exact request/response schemas & error codes vs the live device-management swagger (apidocs.whalebone.io/devicemanagement, not reachable from this build) · userId format (= MSISDN?) · DeviceDetails / list response shapes · content_type full enum · X-day retention value before auto-delete · VPN/pairing token TTL.
